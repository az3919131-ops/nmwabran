# متابعة صرف المواد من الكهرباء

تطبيق ويب لمشروع كهرباء نجران. يقارن لكل مادة بين ثلاثة مصادر:

| المصدر | المعنى | كيف تدخله |
|---|---|---|
| **Checklist** | المطلوب صرفه من شركة الكهرباء | صورة بالكاميرا، أو صورة مرفوعة، أو ملف Excel أو PDF |
| **UDS** | المسجّل على نظام UDS | صورة بالكاميرا، أو صورة مرفوعة، أو ملف Excel أو PDF |
| **Gate Pass** | المصروف فعليًا من المستودع | صورة بالكاميرا، أو صورة مرفوعة، أو ملف Excel أو PDF |

بعد الإدخال يظهر الناقص والزائد بالألوان، ويُصدَّر تقرير Excel يوضح ما هو موجود في Checklist أو UDS ولم يُصرف في Gate Pass.
وصف كل مادة يُؤخذ من **كتالوج الإكسل** حسب رقم المادة (SEC)، وليس مما يُقرأ من الصورة.

> **لماذا ليس Next.js؟** طلبتَ ملفات HTML وCSS وJavaScript بدون خطوة بناء وتعمل بفتح الملف مباشرة. لذلك بُني التطبيق بهذه الطريقة، وهو يستخدم Supabase للحسابات وقاعدة البيانات والصور. لا تحتاج تثبيت أي شيء على جهازك.

---

## 1) جرّبه الآن (دقيقتان، بدون إنترنت تقريبًا)

1. افتح مجلد `materials-tracker`.
2. اضغط ضغطتين على الملف `index.html`. يفتح في المتصفح.
3. اكتب اسمك واضغط **ادخل إلى اللوحة**.
4. اضغط **حمّل المشروع التجريبي**. فيه بيانات من الصورتين اللتين أرسلتهما (Checklist صفحة 3 من 12، وGate Pass صفحة 1 من 4).

هذا هو **الوضع المحلي**: البيانات تُحفظ في متصفحك على هذا الجهاز فقط. لا تنتقل إلى جهاز آخر.
قراءة الصور تحتاج إنترنت أول مرة لتحميل محرك القراءة، ثم تعمل أسرع.

---

## 2) انشره على الإنترنت (Netlify، الأسهل)

1. ادخل إلى <https://app.netlify.com/drop> وسجّل الدخول بحساب مجاني.
2. اسحب مجلد `materials-tracker` كاملًا وأفلته على الصفحة.
3. بعد ثوانٍ يعطيك رابطًا مثل `https://اسم-عشوائي.netlify.app`. افتحه من الجوال.
4. من الجوال: **استيراد القوائم** ثم **صوّر بالكاميرا** تفتح الكاميرا مباشرة. (الكاميرا تحتاج رابط `https` وهو متوفر في Netlify.)

لتغيير الاسم: Site configuration ثم Change site name.

**إن ربطت مستودع GitHub بدل السحب:** اجعل Base directory = `materials-tracker` وPublish directory = `.` وفرّغ خانة Build command.

### بديل: Render

New + ثم Static Site، اختر المستودع، واضبط Root Directory = `materials-tracker` وPublish Directory = `.` وفرّغ Build Command. (يوجد ملف `render.yaml` جاهز.)

## 3) اربطه بقاعدة بيانات حتى يشاهد الفريق نفس البيانات (Supabase)

بدون هذه الخطوة كل جهاز له بياناته الخاصة. معها تتشارك الفريق البيانات والصور بحسابات وكلمات مرور.

**أ) أنشئ المشروع**
1. ادخل إلى <https://supabase.com> وسجّل حسابًا مجانيًا.
2. New project، اكتب اسمًا وكلمة مرور لقاعدة البيانات، واختر أقرب منطقة.

**ب) أنشئ الجداول**
1. من القائمة اليسرى: **SQL Editor** ثم **New query**.
2. افتح الملف `supabase/schema.sql` بأي محرر نصوص، انسخ كل محتواه، والصقه، واضغط **Run**.
3. يجب أن تظهر رسالة نجاح. (يمكن تشغيله مرة ثانية بأمان.)

**ج) أضف المستخدمين وأغلق التسجيل المفتوح**
1. **Authentication** ثم **Providers** ثم **Email**: أوقف **Allow new users to sign up**.
2. **Authentication** ثم **Users** ثم **Add user**: أضف بريد وكلمة مرور لكل فرد في الفريق (مع تفعيل Auto confirm).

> مهم: إذا تركت التسجيل مفتوحًا، يستطيع أي شخص ينشئ حسابًا ويرى بياناتك.

**د) انسخ مفاتيح الاتصال**
1. **Project Settings** ثم **API** (أو Data API).
2. انسخ **Project URL** والمفتاح **anon** (يبدأ بـ `eyJ`). إن لم تجده افتح تبويب **Legacy API keys**.
3. افتح الملف `assets/js/config.js` وضعهما بين علامتي الاقتباس:

```js
window.MT_CONFIG = {
  SUPABASE_URL: 'https://xxxxxxxx.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...',
  BUCKET: 'documents',
};
```

المفتاح العام (anon) آمن للنشر. الحماية الحقيقية بسياسات قاعدة البيانات التي أنشأها `schema.sql`: لا أحد يقرأ شيئًا بدون تسجيل دخول.

**هـ) أعد النشر**
اسحب المجلد من جديد إلى Netlify (أو ارفع التغيير إلى GitHub). افتح الرابط: ستظهر شاشة **ادخل إلى حسابك** بالبريد وكلمة المرور.

الصور تُحفظ في مخزن خاص اسمه `documents` (أنشأه `schema.sql`).

## 4) الاستخدام اليومي

1. **المشاريع**: أنشئ مشروعًا أو افتح موجودًا.
2. **استيراد القوائم**، ثلاث تبويبات: Checklist ثم UDS ثم Gate Pass.
   - أربع طرق للإدخال: **صوّر بالكاميرا**، أو **ارفع صورة أو PPT**، أو **ارفع Excel أو PDF**، أو **الصق**. ملف PDF النصي (المُصدَّر من النظام) يُقرأ مباشرة بدقة كاملة، والممسوح ضوئيًا يُقرأ كالصور. صفحات الملف الواحد تُجمع في قائمة واحدة (حتى 12 صفحة).
   - **الصق**: انسخ جدولًا من Excel أو نصًا من أي برنامج أو لقطة شاشة أو ملفًا، ثم اضغط Ctrl+V في أي مكان من الشاشة، أو اضغط زر **الصق**. الجدول المنسوخ من Excel يذهب إلى ربط الأعمدة، والنص العادي يُقرأ أسطرًا.
   - **PowerPoint وWord**: يُقرأ النص والجداول مباشرة، وتُقرأ الصور الملصوقة داخلها (لقطات الشاشة). الصيغ القديمة ppt وdoc لا يمكن قراءتها، احفظها pptx أو docx أو PDF.
   - للصور: دوّر الصورة إن لزم، ثم **اقرأ الصورة**.
   - **راجع الجدول**: كل صف ملوّن يحتاج نظرتك. الأحمر ناقص كود أو كمية، والأصفر مستنتج أو مصحَّح تلقائيًا. إلى جانب الجدول صورتك الأصلية للمقارنة.
   - اضغط **احفظ في المشروع**.
3. **Gate Pass متعدد الصفحات**: صوّر كل صفحة على حدة. الصفحات التي تحمل نفس رقم الـ Gate Pass تُضاف إلى مستند واحد، وإعادة رفع نفس الصفحة لا تضاعف الكميات.
4. **لوحة المتابعة**: أرقام الأصناف (مطابق، ناقص، زائد، لم يُصرف). اضغط أي بطاقة لترى أصنافها.
5. **مقارنة المواد**: حسب المادة أو حسب **أمر العمل**. أمر العمل يُستخرج من عمود Unloading Point في الـ Checklist، ويُربط بالـ Gate Pass برقم الحجز.
6. **التقارير**: ملخص، وثلاث مقارنات ثنائية، و**الناقص من Gate Pass**، وأوامر العمل. كل تقرير يُنزَّل Excel أو يُطبع PDF.

### كيف يُحسب الوضع

- المصروف الفعلي لكل مادة = مجموع كمياتها في كل مستندات Gate Pass.
- **مطابق**: المصروف = المطلوب. **ناقص**: أقل من المطلوب. **زائد**: أكثر من المطلوب أو مادة لم تُطلب. **لم يُصرف**: مطلوب ولا شيء مصروف.
- لو لا توجد Checklist للمادة يُستخدم UDS كمرجع.
- فرق UDS عن Gate Pass يظهر منفصلًا حتى لا يخلط الحالة الأساسية.

## 5) القراءة الدقيقة بالذكاء الاصطناعي (اختياري)

القراءة المجانية على جهازك جيدة مع Checklist، وتحتاج تصحيحًا أكثر مع Gate Pass المائل أو المكتوب عليه بخط اليد.
للقراءة الدقيقة: افتح **الإعدادات** (من حسابك أعلى اليسار)، والصق مفتاح Anthropic API، واضغط **اختبر المفتاح** ثم **احفظ الإعدادات**. الخيار يصير مفعّلًا تلقائيًا عند كل استيراد، ويمكنك إيقافه من مربع الاختيار في خطوة التجهيز.

- **ما الذي يقرأه:** الصور، وملفات PDF (تُرسل كما هي بنصها وصفحاتها)، وعروض PowerPoint (لقطات الشرائح ونصها)، ومستندات Word، والنص الملصوق.
- **النموذج:** Claude Opus 5.5 افتراضيًا لأنه الأدق. يمكنك اختيار Sonnet 5.5 (أسرع وأرخص) أو Haiku 5.5 (الأرخص) من الإعدادات.
- **المراجعة الثانية:** بعد القراءة يفحص التطبيق كل صف: كود غير موجود في الكتالوج، كمية ناقصة، أو مجموع فرعي مطبوع لا يطابق مجموع الصفوف. الصفوف المشكوك فيها تُرسل إلى Claude مرة ثانية ليعيد قراءتها، ولا تُقبل النتيجة الجديدة إلا إذا قلّلت المشكلات.
- **إن تعذّرت القراءة:** مفتاح خاطئ أو رصيد ناقص أو انقطاع إنترنت، فيُقرأ المحتوى محليًا تلقائيًا ويظهر لك تنبيه بالسبب.
- **الخصوصية والتكلفة:** المفتاح يُحفظ في متصفحك فقط، والمحتوى يذهب إلى Anthropic مباشرة دون خادم وسيط. تظهر لك التكلفة التقريبية بعد كل قراءة.

لم يُجرَّب الاتصال الحقيقي بخدمة Anthropic أثناء التطوير. اختُبر الكود بمحاكاة لردودها (البث، والمخطط، والمراجعة الثانية، والأخطاء). أول قراءة حقيقية بمفتاحك هي الاختبار الفعلي، فراجع صفوفها بعناية.

نصائح لقراءة أفضل في الحالتين: صوّر الورقة مستقيمة، وبإضاءة موزعة، وقرّب الكاميرا من الجدول، وتجنب لمعان الكشاف على الأرقام.

## 6) معلومات مهمة

- **الكتالوج**: 623 صنفًا من ملف الإكسل، بدون الأسعار عمدًا لأن ملفات الموقع الثابتة يراها كل من يملك الرابط. لتحديثه: **كتالوج المواد** ثم **استورد كتالوج Excel** (يدمج الجديد ويحدّث الأوصاف).
- سطر واحد في الإكسل رقم مادته `52` (محول 300KVA) فتم تجاهله لأن أرقام SEC تتكون من 9 أرقام. صحّحه في الملف الأصلي ثم أعد استيراده.
- **المشروع التجريبي** يحمل أرقام حجز حقيقية من الصورتين. احذفه من شاشة المشاريع قبل النشر العام إن لم ترد ظهورها.
- ملفات التطبيق ثابتة وعامة لمن يملك الرابط. بياناتك الفعلية محمية في Supabase خلف الدخول.
- في الوضع المحلي: نزّل نسخة احتياطية من **الإعدادات** قبل مسح بيانات المتصفح أو تغيير الجهاز.
- كل ملف Excel مُصدَّر ينتهي بسطر **Project Manager | Eng. Ahmed Zahran**، وكذلك كل صفحة مطبوعة، وكل صفحة في التطبيق.
- بعد النشر ضع الرابط الكامل لصورة المشاركة في وسوم `og:image` و`twitter:image` داخل `index.html` (مثال: `https://موقعك.netlify.app/assets/img/og.webp`) حتى تظهر عند مشاركة الرابط في واتساب.

## للمطوّر

```
materials-tracker/
  index.html               نقطة الدخول (بدون خطوة بناء)
  assets/css/app.css       نظام التصميم
  assets/js/core.js        أدوات + كتالوج المواد
  assets/js/compare.js     محرك المقارنة (دوال نقية)
  assets/js/parsers.js     تحليل نص OCR وجداول Excel إلى صفوف
  assets/js/pdf.js         قراءة ملفات PDF (نص مضمّن أو صفحات ممسوحة)
  assets/js/ocr.js         Tesseract.js: اتجاه الصورة وتحسينها
  assets/js/ai.js          القراءة الدقيقة بـ Claude (Anthropic API من المتصفح)
  assets/js/office.js      قراءة pptx وdocx (نص وجداول وصور)
  assets/js/store.js       التخزين: محلي أو Supabase + الدمج ومنع التكرار
  assets/js/views/*.js     الشاشات
  supabase/schema.sql      الجداول وRLS والتخزين وعرض الملخص
  tools/build-catalog.py   يحوّل إكسل الكتالوج إلى assets/js/catalog-data.js
  tests/                   اختبارات Node واختبارات متصفح (Playwright)
```

الاختبارات السريعة: `npm test` (المقارنة، المحللات على مخرجات OCR الحقيقية، التخزين، محوّل Supabase).
اختبارات المتصفح وقاعدة البيانات تحتاج تثبيت `playwright-core exceljs xlsx tesseract.js @tesseract.js-data/eng axe-core @electric-sql/pglite` خارج المشروع، ثم `E2E_DEPS=/المسار/node_modules node tests/e2e/flow.cjs`.

المكتبات الخارجية تُحمَّل عند الحاجة فقط وبإصدارات محددة: SheetJS 0.18.5 وExcelJS 4.4.0 وTesseract.js 5.1.1 وpdf.js 3.11.174 وJSZip 3.10.1 وsupabase-js 2.45.4.
